# Design context: Bouncer

- **Audience:** developers running many AI coding agents at once on one Mac.
- **Use cases:** glance "is my Mac OK and what's waiting"; act on one job (let it in first, stop it); notice when something outside Bouncer is eating memory.
- **Tone:** calm door staff. Quiet when everything is fine, firm and specific when it isn't. States: *Clear*, *Tight*, *Holding the door*.
- **Constraints:** native macOS menu bar, opened many times a day: no open/close animation, no perpetual motion (a load monitor must not cost load), system font with monospaced digits, semantic colours for light/dark, one accent = load colour. The CLI follows the same vocabulary and hierarchy (`src/term.ts`).
- **Review:** render every state with `BouncerBar --snapshot <dir> --status-file docs/demo-status*.json` (also `not-running`, `not-installed`) and look at light and dark before shipping UI changes.
